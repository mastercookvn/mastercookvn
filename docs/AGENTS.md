# Docs

Written using Vitepress, prefer using mermaid. Only specific diagram that doesn't support, fallback to PlantUML

## Structure

```
src
├── index.md                    # Home
├── specification.md            # Business specification and rules
├── nghiep-vu/                  # Parameters, UC catalog and business topics
│   ├── index.md
│   └── [business topic]/       # Use cases and related workflows
├── mo-hinh/                    # System-wide domain model
├── public/diagrams/            # Generated by vitepress-plugin-diagrams
└── references/                 # References, including _old_report/ archive
```

Keep the UC catalog and business topic indexes synchronized with their documents. Use numeric frontmatter `order` to arrange sidebar items within each folder.

`src/nghiep-vu/tham-so.md` is the source of truth for parameter values and limits; keep BRs, use cases and models aligned with it. Keep the domain model simple and implementable.

## Rules

### Class

Spring Boot Java designed, Use hibernate ORM

### Description around diagram

PlantUML diagrams inside markdown codeblocks need a comment below for `vitepress-plugin-diagrams` cache management. Mermaid diagrams do not require this comment.

Every change in the diagram will be detected to clean up the old diagram, and create new, in `./src/public/diagrams/`

With the format of like `plantuml-vitepress-plugin-digrams-use-case-example-b6de774ff81a44366a862d86df5d7ad4.svg`, the suffix is a hash of the diagram content

```markdown
<!-- diagram id="vitepress-plugin-digrams-[diagram type]-[name]" -->
<!-- diagram id="vitepress-plugin-digrams-use-case-example" -->
<!-- diagram id="vitepress-plugin-digrams-class" -->
<!-- No -[name] if we don't have other instance of that same type -->
```
