# Docs

Written using Vitepress, prefer using mermaid. Only specific diagram that doesn't support, fallback to PlantUML

## English translation

- `docs-en/` is the English review copy of the maintained pages in `docs/`; never edit the Vietnamese source while translating or reviewing this package.
- Keep matching filenames and relative links so every English page can be compared directly with its Vietnamese source.
- The Vietnamese docs remain the behavioural contract. Use `web/` only as the source for established English terminology; frontend mocks must not override documented rules.
- Preserve BR/UC/TS identifiers, formulas, numeric thresholds, routes, code, enum/status literals, and diagram semantics.
- Preferred domain terms include `Booking` for the customer workflow, `Order` for `DonDatTiec`, `Meal` for `BuaTiec`, `serving table` for `ban an`, `setup table` for `ban bo tri`, `Equipment` for `DungCu`, `Contract Addendum`, `Meal Settlement`, `Stocktake`, and `on-behalf order`.

## Rules

### Class

Spring Boot Java designed, Use hibernate ORM

### Description around diagram

Each diagram inside markdown codeblock has to have a comment below of it, for npm package `vitepress-plugin-diagrams` to work with cache. If not provide, the cache will flood the storage.

Every change in the diagram will be detected to clean up the old diagram, and create new, in `./src/public/diagrams/`

With the format of like `plantuml-vitepress-plugin-digrams-use-case-example-b6de774ff81a44366a862d86df5d7ad4.svg`, the suffix is a hash of the diagram content

```markdown
<!-- diagram id="vitepress-plugin-digrams-[diagram type]-[name]" -->
<!-- diagram id="vitepress-plugin-digrams-use-case-example" -->
<!-- diagram id="vitepress-plugin-digrams-class" -->
<!-- No -[name] if we don't have other instance of that same type -->
```
